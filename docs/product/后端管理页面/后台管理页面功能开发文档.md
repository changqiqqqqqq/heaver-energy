# 河狸数字能源后台管理页面功能开发文档

## 1. 文档目标

本文档基于 `docs/product/后端管理页面/Container.png` 后台原型，结合当前仓库 `apps/admin-web` 与 `services/api` 已有能力，梳理后台管理页面的功能范围、数据口径、前后端分工、接口依赖和开发顺序。

后台定位为运营数据后台，服务对象为河狸数字能源内部运营、顾问、渠道与管理人员。MVP 阶段优先支持小程序测评后的线索承接、数据看板、消息跟进和供应商转接。

## 2. 原型页面功能概览

原型页面为「今日数据」看板，整体由左侧导航、顶部工具栏、核心指标卡、趋势图、转化漏斗、测评结果分布、消息待回复组成。

### 2.1 左侧导航

| 一级分组 | 菜单 | 功能说明 | MVP 优先级 |
| --- | --- | --- | --- |
| 数据概览 | 今日数据 | 查看今日点击、测评、报告领取、顾问咨询等核心指标 | P0 |
| 数据概览 | 趋势分析 | 查看多日趋势、指标对比、渠道变化 | P1 |

## 4. 功能模块设计

### 4.1 后台登录与权限

页面：

- `/login`
- 登录后进入 `/`

功能：

- 管理员输入用户名、密码登录。
- 登录成功保存 token。
- 所有 `/api/admin/*` 请求携带 `Authorization: Bearer <token>`。
- token 失效跳转登录页。
- 顶部展示管理员姓名，支持退出登录。

后端接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/admin/auth/login` | 管理员登录 |
| GET | `/api/admin/auth/me` | 获取当前管理员 |
| POST | `/api/admin/auth/logout` | 退出登录 |

前端开发点：

- 补齐 `auth.api.ts`、`auth.store.ts`、`http.ts`。
- 在 `AdminLayout` 中增加登录态校验。
- 处理 401 自动跳转。

### 4.2 后台整体布局

页面骨架：

- 左侧固定导航，宽度建议 228px。

## 5. 数据口径设计

### 5.1 今日点击人数

当前后端暂无埋点表，建议新增事件表或统计事件模块。

推荐表：`operation_events`

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `user_id` | 用户 ID，可为空 |
| `anonymous_id` | 匿名访客 ID |
| `event_name` | 事件名，如 `miniapp_enter`、`questionnaire_start` |
| `source_channel` | 来源渠道 |
| `page_path` | 页面路径 |
| `detail_json` | 扩展数据 |
| `occurred_at` | 事件发生时间 |

MVP 替代口径：

- 如果没有事件表，可暂用当日新线索数或当日进入测评人数反推，但需在页面标注“访问埋点未接入”。

### 5.2 今日答题人数

推荐口径：

- 当日 `questionnaire_submissions.created_at` 的去重用户数或提交次数。
- 原型展示“人数”，建议按去重 `user_id` 统计；用户为空时按提交次数兜底。

### 5.3 今日报告领取

推荐口径：

- 当日 `screening_requests.submitted_at` 数量。
- 或线索 `source_entry=screening` 的新增/更新数量。

### 5.4 顾问咨询预约

推荐口径：

- 当日 `service_requests.submitted_at` 数量。

### 5.5 画像预约率

计算方式：

```text
画像预约率 = 该画像下提交顾问咨询人数 / 该画像下完成测评人数
```

关联方式：

- 优先使用 `questionnaire_submissions.lead_id` 与 `service_requests.lead_id`。
- 若同一线索多次咨询，按线索去重。

## 9. 性能与安全要求

### 9.1 性能

- 看板首屏优先使用聚合接口，避免前端同时请求过多接口。
- 线索列表必须分页，默认 `page_size=20`。
- 趋势和分布类查询按日期范围聚合，后端避免返回明细后由前端计算。
- 常用筛选字段保持数据库索引：`lead_status`、`lead_grade`、`profile_code`、`last_activity_at`。
- 后台页面使用组件级加载态，避免全页阻塞。

### 9.2 安全

- 所有后台接口必须登录后访问。
- 敏感手机号只能通过独立接口查看，并写入审计日志。
- 前端默认展示脱敏手机号。
- 导出报表需要记录管理员、时间范围和导出动作。
- 权限模型首期可只做登录校验，后续接入角色权限。
